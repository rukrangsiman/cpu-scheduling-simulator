# CPU Scheduling Simulator

โปรแกรมจำลองการจัดลำดับการใช้หน่วยประมวลผล (CPU Scheduling) แบบ Web Application
สำหรับ Term Project รายวิชา ______________________

เปรียบเทียบ 3 อัลกอริทึมบนชุดข้อมูลเดียวกัน

- **FCFS** — First-Come, First-Served
- **SJF** — Shortest Job First แบบ Non-preemptive
- **RR** — Round Robin (กำหนด Time Quantum ได้ ค่าเริ่มต้น 2)

ทุกโปรเซสมี Arrival Time = 0 และเรียงลำดับเริ่มต้นเป็น P1, P2, …, Pn ตามที่โจทย์กำหนด

## 2. วิธีใช้โปรแกรม

หน้าจอแบ่งเป็น 2 ส่วน: **แถบ CPU ด้านซ้าย** (สีเข้ม ลอยแยกจากเนื้อหา) ใช้ตั้งค่า และ **พื้นที่ตรงกลาง** แสดงผลลัพธ์ของ CPU ที่เลือกอย่างเดียว
กด **โลโก้มุมซ้ายบน** เพื่อซ่อน/แสดงแถบ CPU (ซ่อนแล้วเหลือกล่องเล็ก ๆ ที่มีแค่โลโก้ พื้นที่ผลลัพธ์กว้างขึ้น และจำไว้ในเครื่อง)
บนแท็บเล็ตและมือถือ (จอแคบกว่า 1024px) เรียงเป็น ชื่อโปรแกรม → แถบ CPU → ผลลัพธ์

1. **แถบ CPU ด้านซ้าย — สร้าง CPU ได้หลายตัว เหมือนโปรไฟล์**
   - CPU แต่ละตัวมีชุดข้อมูลของตัวเอง (จำนวนโปรเซส, Burst Time, สี, Time Quantum และผลการ Run ล่าสุด) แต่ละการ์ดแสดงจำนวนโปรเซส, TQ, สถานะ (ยังไม่ Run / Run แล้ว / ผลเก่า) และแท่งเล็ก ๆ แทน BT
   - **กดการ์ด CPU** = เลือก CPU นั้นเพื่อดูผลลัพธ์ / **กดปุ่มลูกศร ⌄ มุมขวาล่างของการ์ด** = การตั้งค่าการจำลองกางลงมาเป็น dropdown ใต้การ์ด (การ์ดกับแผงตั้งค่ากลายเป็นแผ่นสีครีมแผ่นเดียว) กดลูกศรอีกครั้งเพื่อพับ
   - ปุ่ม **⋯** บนการ์ดเปิด popup รายละเอียด CPU กด **+ เพิ่ม CPU** เพื่อสร้างตัวใหม่ (4 โปรเซส สุ่ม BT) สร้างได้สูงสุด 12 ตัว
   - โปรแกรมจำ CPU ทุกตัวไว้ในเครื่อง ปิดแล้วเปิดไฟล์ใหม่ยังอยู่
2. **แผงตั้งค่าการจำลอง** (dropdown ใต้การ์ด CPU ที่เลือก)
   - **จำนวนโปรเซส** (1–20) พิมพ์หรือกด **− / +** แถว P1 ถึง Pn (เรียง 2 คอลัมน์) เพิ่ม/ลดตามทันที (ค่า Burst Time ที่กรอกไว้แล้วไม่หาย) และ **Time Quantum** (ค่าเริ่มต้น 2 ใช้กับ Round Robin)
   - วิธีกำหนด Burst Time: **สุ่ม (1–10)** — ช่องแก้ไม่ได้ กด **สุ่ม Burst Time ใหม่** เพื่อสุ่มอีกครั้ง / **กรอกเอง** — กรอกจำนวนเต็ม 1–100
   - ทุกโปรเซสมี AT = 0 (แสดงที่หัวแผง)
   - กดจุดสีหน้าชื่อโปรเซสเพื่อเลือกสีที่ใช้ใน Gantt chart ตาราง สูตร และแถบ CPU: เลือกจาก **สีตัวอย่าง** 20 สี หรือกด **กำหนดเอง (RGB)** (ปุ่ม **ใช้สีเริ่มต้น** คืนค่าสีเดิม)
   - กด **RUN** (หรือกด Enter ในช่องใดก็ได้) ระบบคำนวณ FCFS, SJF และ RR จากชุดข้อมูลเดียวกัน
   - ถ้าแก้ข้อมูลหลัง Run จะมีข้อความเตือนว่าผลเป็นของข้อมูลเดิม และปุ่ม Run มีวงแหวนสีทอง
3. **พื้นที่ผลลัพธ์ตรงกลาง** — หัวบอกชื่อ CPU และสถานะ แท็บ **FCFS / SJF / RR** สลับดูผลได้ทันทีโดยไม่ต้องคำนวณใหม่ ปุ่ม **⋯** ข้างแท็บเปิด popup รายละเอียด CPU ที่เลือก แต่ละแท็บมี
   - ชื่อเต็มและคำอธิบายสั้นของอัลกอริทึม + ปุ่ม **วิธีทำงาน** (เปิด popup อธิบายพร้อมภาพ)
   - **Gantt Chart** แสดงลำดับการได้ CPU ความกว้างแถบตามเวลาจริง ชี้เมาส์หรือกด Tab ไปที่แถบเพื่อดูเวลาเริ่ม / สิ้นสุด / ระยะเวลา (ถ้าแถบเยอะ เลื่อนแนวนอนได้)
   - ค่าสรุป 4 ช่อง: **AVG WT**, **AVG TAT** (พร้อมที่มาของตัวเลข เช่น `(0 + 5 + 8 + 16) ÷ 4 = 7.25`), **เวลารวม** และ **จำนวนครั้งที่สลับโปรเซส**
   - ตาราง Process, AT, BT, ST, CT, TAT, WT และค่าเฉลี่ย — ติ๊ก **แสดงวิธีคำนวณ TAT / WT ในตาราง** เพื่อดูการแทนค่าทีละแถว
   - ส่วน **สูตรการคำนวณของแต่ละค่า** (พับไว้ตอนแรก กดหัวข้อเพื่อกาง/พับ) บอกความหมายและสูตรของ AT, BT, ST, CT, TAT, WT, AVG TAT, AVG WT พร้อมแทนค่าด้วยตัวเลขจริงของโปรเซสที่เลือก
4. แท็บ **เปรียบเทียบ** แสดงกราฟและตาราง AVG WT / AVG TAT ของทั้ง 3 อัลกอริทึม
   เปลี่ยนค่า Time Quantum แล้วกด Run อีกครั้ง ระบบจะใช้ชุด Burst Time เดิมและเพิ่มแถวในตาราง
   "Round Robin เมื่อเปลี่ยน Time Quantum" เพื่อเทียบผลหลายค่า

## 3. หลักการคำนวณ

### สูตร

| ค่า | ความหมาย | สูตร |
|---|---|---|
| AT | Arrival Time — เวลาที่โปรเซสมาถึง | = 0 ทุกโปรเซส |
| BT | Burst Time — เวลาที่ต้องใช้ CPU | ผู้ใช้กำหนด / สุ่ม |
| ST | Start Time — เวลาที่ได้ CPU **ครั้งแรก** | จากการจำลอง |
| CT | Completion Time — เวลาที่ทำงานเสร็จสมบูรณ์ | จากการจำลอง |
| TAT | Turnaround Time | CT − AT (= CT เพราะ AT = 0) |
| WT | Waiting Time | TAT − BT |
| AVG WT | Average Waiting Time | ผลรวม WT ÷ จำนวนโปรเซส |

### กติกาของแต่ละอัลกอริทึม

- **FCFS** — รันตามลำดับ P1 → Pn ทีละโปรเซสจนเสร็จ
- **SJF (Non-preemptive)** — เรียงตาม BT จากน้อยไปมาก ถ้า BT เท่ากันให้หมายเลขน้อยกว่าได้ก่อน (เช่น P1 ก่อน P3) แล้วรันจนเสร็จ
- **Round Robin** — คิวเริ่มต้น P1 → Pn แต่ละโปรเซสได้ CPU ครั้งละ `min(Time Quantum, เวลาที่เหลือ)`
  ถ้ายังไม่เสร็จให้ต่อท้ายคิว ไม่คิดเวลาสลับโปรเซส (context switch overhead)

**ทำไมไม่มี SJF แบบ Preemptive แยก:** เมื่อทุกโปรเซสมาถึงเวลา 0 พร้อมกัน จะไม่มีโปรเซสใหม่เข้ามาระหว่างทาง
โปรเซสที่กำลังรันจึงมีเวลาที่เหลือสั้นที่สุดตลอด แบบ Preemptive (SRTF) จึงให้ผลเหมือน Non-preemptive ทุกกรณี

รายละเอียดการตัดสินใจออกแบบทั้งหมดอยู่ใน [docs/DECISIONS.md](docs/DECISIONS.md)

## 6. ตัวอย่างข้อมูลสำหรับทดสอบ

กรณีทดสอบทั้งหมดพร้อมค่าคาดหวังอยู่ใน [docs/TEST_CASES.md](docs/TEST_CASES.md)

### TC-01 — กำหนด Burst Time เอง เปรียบเทียบ 3 อัลกอริทึม

ข้อมูล: P1 = 5, P2 = 3, P3 = 8, P4 = 6 (เลือก "กรอกเอง" แล้วกรอกในแผงตั้งค่า)

**FCFS** — Gantt: `P1 0–5 | P2 5–8 | P3 8–16 | P4 16–22`

| Process | AT | BT | ST | CT | TAT | WT |
|---|---|---|---|---|---|---|
| P1 | 0 | 5 | 0 | 5 | 5 | 0 |
| P2 | 0 | 3 | 5 | 8 | 8 | 5 |
| P3 | 0 | 8 | 8 | 16 | 16 | 8 |
| P4 | 0 | 6 | 16 | 22 | 22 | 16 |

AVG WT = (0 + 5 + 8 + 16) ÷ 4 = **7.25**

**SJF** — Gantt: `P2 0–3 | P1 3–8 | P4 8–14 | P3 14–22`

| Process | AT | BT | ST | CT | TAT | WT |
|---|---|---|---|---|---|---|
| P1 | 0 | 5 | 3 | 8 | 8 | 3 |
| P2 | 0 | 3 | 0 | 3 | 3 | 0 |
| P3 | 0 | 8 | 14 | 22 | 22 | 14 |
| P4 | 0 | 6 | 8 | 14 | 14 | 8 |

AVG WT = (3 + 0 + 14 + 8) ÷ 4 = **6.25**

**Round Robin (TQ = 2)** — Gantt: `P1 0–2 | P2 2–4 | P3 4–6 | P4 6–8 | P1 8–10 | P2 10–11 | P3 11–13 | P4 13–15 | P1 15–16 | P3 16–18 | P4 18–20 | P3 20–22`

| Process | AT | BT | ST | CT | TAT | WT |
|---|---|---|---|---|---|---|
| P1 | 0 | 5 | 0 | 16 | 16 | 11 |
| P2 | 0 | 3 | 2 | 11 | 11 | 8 |
| P3 | 0 | 8 | 4 | 22 | 22 | 14 |
| P4 | 0 | 6 | 6 | 20 | 20 | 14 |

AVG WT = (11 + 8 + 14 + 14) ÷ 4 = **11.75**

ผลการคำนวณชุดนี้ตรวจด้วยมือโดย ______________ (ดูรายละเอียดใน [docs/TEST_CASES.md](docs/TEST_CASES.md))

### TC-02 — ชุดข้อมูลเดิม เปลี่ยน Time Quantum

| Time Quantum | AVG WT | AVG TAT | จำนวนครั้งที่สลับโปรเซส |
|---|---|---|---|
| 2 | 11.75 | 17.25 | 11 |
| 4 | 10.75 | 16.25 | 6 |
| 10 | 7.25 | 12.75 | 3 |

เมื่อ Time Quantum มากกว่าหรือเท่ากับ BT สูงสุด Round Robin จะให้ผลเหมือน FCFS

### TC-03 — ให้ระบบสุ่ม Burst Time

กรอกจำนวนโปรเซส 10 เลือก "สุ่ม (1–10)" แล้วกด Run
ผลที่ถูกต้อง: ตารางครบ 10 แถวทั้ง 3 อัลกอริทึม และ CT สูงสุดเท่ากับผลรวม BT

   > "เริ่มทำ validation.js กับ UI ต่อเลย"

### ตัวอย่างการตรวจสอบผลลัพธ์จาก AI

- **ใส่ bug โดยตั้งใจ (mutation test):** แก้สำเนาของ `scheduler.js` ให้ผิด 5 แบบ เช่น ให้ Round Robin บันทึก ST ใหม่ทุกรอบ
  ชุดทดสอบ (ตอนนั้นมี 17 ข้อ) จับได้ครบทั้ง 5 แบบ แสดงว่าชุดทดสอบตรวจได้จริง
- **ตรวจแบบอิสระ:** ให้ AI อีกตัวคำนวณมือ 4 ชุดข้อมูลโดยไม่ดูโค้ดก่อน แล้วเทียบกับผลของโปรแกรม ตรงกันทุกช่อง
- **ปัญหาที่พบและแก้:** บนจอมือถือ ข้อความแจ้งเตือนอยู่นอกหน้าจอ ผู้ใช้มองไม่เห็น จึงเพิ่มการเลื่อนหน้าไปที่ข้อความเตือน
