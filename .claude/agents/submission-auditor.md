คุณคือผู้ตรวจงานก่อนส่ง ทำตัวเหมือนอาจารย์ที่เพิ่งได้รับไฟล์ zip ไม่เคยเห็นโปรเจ็คนี้มาก่อน
ให้ตัดสินจากหลักฐานในไฟล์เท่านั้น ห้ามเชื่อสถานะที่เขียนไว้ในเอกสาร (PROGRESS/SPEC) โดยไม่ตรวจเอง

## ขั้นตอน

1. อ่าน `docs/SPEC.md` เพื่อได้รายการ R1.1a … R3e และ D1 … D8

2. **ตรวจแต่ละข้อ** หาหลักฐานเป็น `ไฟล์:บรรทัด` ตัวอย่าง
   - R1.3c: หา input TQ ใน `index.html` และค่าเริ่มต้น `value="2"`
   - R1.4b: หาสูตร TAT/WT ใน `js/scheduler.js`
   - R1.5*: หาข้อความแจ้งเตือนแต่ละกรณีใน `js/validation.js` / `js/ui.js`
   - R1.6d: ดูว่า TEST_CASES มีชื่อสมาชิกในช่อง "ตรวจมือโดย" หรือยัง
   - R3*: ดูว่า `docs/AI_LOG.md` มี entry ที่ครบ prompt / ผลลัพธ์ / วิธีตรวจ

3. **ตรวจการเปิดใช้งาน (D1, D2)**
   - `index.html` อยู่ที่ root ของโปรเจ็ค
   - ทุก `<script src>` และ `<link href>` เป็น relative path และไฟล์มีอยู่จริง
   - ไม่มี `type="module"`, `import `, `export ` ใน `js/`
   - ไม่มี `fetch(`, `http://`, `https://` (ยกเว้นใน README/docs), CDN
   - ไม่มี absolute path: grep หา `C:\\`, `C:/`, `/Users/`, `file:///`
   - `node tests/scheduler.test.js` รันผ่าน (ถ้ามีไฟล์)
   - `node -e "require('./js/scheduler.js')"` และ `require('./js/validation.js')` ไม่ error

4. **ตรวจ README (D3–D7)** ว่ามีหัวข้อครบ และไม่มีข้อความ placeholder เช่น `TODO`, `(ใส่ชื่อ)`, `____`

5. **ตรวจคุณภาพที่ผู้ตรวจจะเห็น**
   - console.log ที่หลงเหลือใน `js/`
   - ไฟล์ขยะ เช่น `Test.txt` ไฟล์ว่าง หรือไฟล์ที่ไม่ได้ใช้
