### AI-002 — เขียนอัลกอริทึม FCFS / SJF / RR และไฟล์ทดสอบ

  - `tests/scheduler.test.js`: ทดสอบค่าจาก TEST_CASES, tie-break ของ SJF, ข้อมูลผิด และสุ่ม 500 ชุดเพื่อตรวจเงื่อนไขที่ต้องจริงเสมอ (Gantt ต่อกันไม่มีช่องว่าง, ผลรวมเวลาใน Gantt = BT, SJF AVG WT ≤ FCFS และ RR)
- **ไฟล์ที่เกี่ยวข้อง:** `js/scheduler.js`, `tests/scheduler.test.js`
- **ตรวจสอบอย่างไร:**
  - `node tests/scheduler.test.js` ผ่าน 17/17 และค่าคาดหวังของ TEST_CASES ถูกตรวจซ้ำด้วยสคริปต์ Python ที่เขียนแยก (ไม่ได้ใช้โค้ด JS) ได้ค่าตรงกัน
  - **ทดสอบว่า test จับ bug ได้จริง (mutation test):** จงใจใส่ bug ลงในสำเนาของ scheduler.js แล้วรัน test — จับได้ครบทั้ง 5 แบบ

    | SJF tie-break กลับด้าน (`b - a`) | ล้ม 2 ข้อ |
    | RR บันทึก ST ใหม่ทุกรอบ | ล้ม 5 ข้อ |
    | RR ใส่โปรเซสที่ยังไม่เสร็จไว้หัวคิวแทนท้ายคิว | ล้ม 3 ข้อ |
    | WT ผิดเฉพาะตอน BT = 10 | ล้ม 1 ข้อ (จับได้จากข้อมูลสุ่มเท่านั้น) |
    | RR ใช้ CPU เต็ม quantum แม้เหลือเวลาน้อยกว่า | ล้ม 6 ข้อ |

- **วันที่:** 2026-10-12
- **ผู้ใช้ AI:** _(ใส่ชื่อ)_

- **หมวด:** ตรวจผลการคำนวณ
- **Prompt:** (AI หลักสั่ง subagent) "คำนวณมือทีละขั้นก่อน โดยห้ามเปิด js/scheduler.js และ tests/ … แล้วจึงรันโค้ดเทียบ" กับ TC-01 (TQ 2, 4) และชุดสุ่ม 3 ชุด

  - เพิ่ม `Scheduler.countContextSwitches()` ใช้ในตารางเปรียบเทียบ TQ

  1. Browser pane เปิด `file://` เป็นภาพนิ่ง CSS/JS ไม่ทำงาน → ทดสอบผ่าน local server (`python -m http.server`) แทน ส่วนผู้ตรวจยังเปิดไฟล์ตรงได้เพราะไม่ใช้ module/fetch
  2. บนจอมือถือ กด "สร้างตาราง" ด้วยค่าผิดแล้วมองไม่เห็นข้อความเตือน เพราะกล่องอยู่ใต้ปุ่มคำนวณ → เพิ่มการเลื่อนหน้าไปที่กล่องแจ้งเตือน
