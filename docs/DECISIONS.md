# DECISIONS — บันทึกการตัดสินใจออกแบบ

สถานะ: 🟦 เสนอ (รอผู้ใช้ยืนยัน) · ✅ ยืนยันแล้ว · ❌ ยกเลิก
AI ต้องไม่เปลี่ยนรายการ ✅ โดยไม่ถามผู้ใช้ ถ้าต้องการเปลี่ยนให้เพิ่มรายการใหม่ที่อ้างถึงรายการเดิม

### D-001 เทคโนโลยี — ✅
Vanilla HTML/CSS/JS เปิด `index.html` ได้ทันทีด้วย double-click
**เหตุผล:** โจทย์แนะนำ, ผู้ตรวจไม่ต้องติดตั้งอะไร, ไม่ต้องอธิบาย framework ในวิดีโอ
**ผลที่ตามมา:** ห้ามใช้ ES modules (Chrome บล็อกบน `file://`) ให้ใช้ `<script src>` ธรรมดา

### D-002 โครงสร้างไฟล์ — ✅
```
index.html            หน้าเดียว
css/style.css
js/scheduler.js       Role A — อัลกอริทึม (pure)
js/validation.js      Role B — ตรวจ input (pure)
js/ui.js              Role B — DOM, render ตาราง/Gantt
tests/scheduler.test.js   รันด้วย `node tests/scheduler.test.js` (สำหรับทีมพัฒนา ผู้ตรวจไม่จำเป็นต้องรัน)
docs/                 เอกสารการทำงาน
README.md
```
**เหตุผล:** แยกไฟล์ตาม Role ทำให้แต่ละคนทำงานคู่ขนานและอธิบายในวิดีโอได้ว่าใครทำส่วนไหน

### D-003 SJF tie-break — ✅
ถ้า BT เท่ากัน ให้โปรเซสที่มีหมายเลขน้อยกว่าได้ก่อน (P1 ก่อน P2)
**เหตุผล:** เทียบเท่า FCFS ในกรณีเสมอ เป็นธรรมเนียมในตำรา และทำให้ผลลัพธ์ deterministic
**วิธีทำ:** ใช้ stable sort หรือเปรียบเทียบ index เมื่อ BT เท่ากัน

### D-004 กติกา Round Robin — ✅
- Ready queue เริ่มต้น P1, P2, …, Pn
- โปรเซสได้ CPU นาน `min(quantum, เวลาที่เหลือ)`
- ถ้ายังไม่เสร็จ ต่อท้ายคิว ถ้าเสร็จ บันทึก CT
- ST = เวลาที่ได้ CPU **ครั้งแรก**
- ไม่คิด context switch overhead
**หมายเหตุ:** เพราะ AT = 0 ทั้งหมด จึงไม่มีความกำกวมเรื่อง "โปรเซสมาใหม่ vs โปรเซสที่ถูก preempt ใครเข้าคิวก่อน"

### D-005 SJF Preemptive (SRTF) — ✅
ไม่ทำเป็นอัลกอริทึมแยก
**เหตุผล:** เมื่อทุกโปรเซสมี AT = 0 จะไม่มีโปรเซสใหม่เข้ามาระหว่างทาง โปรเซสที่กำลังรันจึงมีเวลาที่เหลือสั้นที่สุดตลอด
SRTF จึงให้ผล**เหมือน SJF Non-preemptive ทุกกรณี** ประเด็นนี้ใช้อธิบายในวิดีโอเพื่อแสดงความเข้าใจได้
**ทางเลือก:** ถ้ากลุ่มอยากได้คะแนน optional อาจเพิ่ม SRTF และแสดงให้เห็นว่าผลเท่ากัน

### D-006 ขอบเขตค่า input — ✅
| ค่า | ช่วงที่รับ | เหตุผล |
|---|---|---|
| จำนวนโปรเซส n | 1 – 10 (เดิม 1 – 20 เปลี่ยนใน **D-036**) | ตารางและ Gantt ยังอ่านออก |
| BT (กรอกเอง) | 1 – 100 | กัน Gantt ยาวเกินจอ |
| BT (สุ่ม) | 1 – 10 | ตัวเลขเล็ก คำนวณมือตรวจได้ |
| Time Quantum | 1 – 100, ค่าเริ่มต้น 2 | ตามโจทย์ |

### D-007 รูปแบบ input ที่ถือว่า "จำนวนเต็มบวก" — ✅
ตัดช่องว่างหัวท้าย แล้วต้องตรงกับ `/^\d+$/` และมีค่า ≥ 1
ปฏิเสธ: `""`, `"0"`, `"-3"`, `"2.5"`, `"abc"`, `"1e2"`, `"+3"`
**เหตุผล:** `parseInt("2.5")` ได้ 2 และ `Number("1e2")` ได้ 100 ซึ่งจะทำให้ค่าผิดโดยผู้ใช้ไม่รู้ตัว

### D-008 การใช้ชุดข้อมูลเดียวกัน — ✅
- กด "คำนวณ" แล้วคำนวณทั้ง 3 อัลกอริทึมจากชุดข้อมูล snapshot เดียว
- แสดงเป็นแท็บ FCFS / SJF / RR + แท็บ "เปรียบเทียบ" (ตาราง AVG WT / AVG TAT)
- เปลี่ยน TQ แล้วคำนวณใหม่ → BT ไม่เปลี่ยน (ไม่สุ่มใหม่)
- เก็บประวัติผล RR หลายค่า TQ ไว้เทียบกัน (รองรับ R1.6c)

### D-009 ฟีเจอร์เสริม — ✅
> ปุ่ม "ใช้ข้อมูลตัวอย่าง" ถูกลบใน **D-018** (ผู้ใช้ขอ) — Gantt chart ยังมีตามเดิม
- Gantt chart ของแต่ละอัลกอริทึม (ช่วยตรวจผลและอธิบายในวิดีโอ)
- ปุ่ม "ใช้ข้อมูลตัวอย่าง" ใส่ชุดข้อมูล TC-01 จาก TEST_CASES แล้วคำนวณทันที (ใช้ตอนถ่ายวิดีโอ)
ฟีเจอร์เสริมทำหลังจากข้อกำหนดหลักเสร็จเท่านั้น

### D-010 ภาษาและการแสดงผล — ✅
- Label/ข้อความแจ้งเตือนเป็นภาษาไทย หัวตารางเป็นตัวย่อภาษาอังกฤษตามโจทย์ (Process, AT, BT, ST, CT, TAT, WT)
- AVG แสดงทศนิยม 2 ตำแหน่ง
- Comment ในโค้ดเป็นภาษาไทย

### D-011 หน้าเว็บแบบทีละขั้น + สีของโปรเซส + ปุ่มสลับธีม — ✅ (ผู้ใช้ขอ 2026-10-12)
> ส่วน "แบ่งเป็น 4 ขั้น" ถูกแทนด้วย Dashboard ใน **D-013** (สีของโปรเซสและธีมยังใช้ตามเดิม)

ผู้ใช้เห็นว่าหน้าเดิม "ดูเยอะไปหมด" จึงขอให้แยกเป็นทีละลำดับ เลือกสีแต่ละโปรเซสได้ และสลับธีมมืด/สว่างได้
- ยังเป็น `index.html` ไฟล์เดียวตาม D-002 แต่แบ่งเป็น 4 ขั้น แสดงทีละขั้น (ซ่อน/แสดงด้วย `hidden`):
  1) จำนวนโปรเซส + วิธีกำหนด BT → 2) Burst Time และสี → 3) Time Quantum → 4) ผลลัพธ์
- ปุ่ม "ถัดไป" ตรวจข้อมูลของขั้นนั้นก่อนไปต่อ และตอนกดคำนวณจะตรวจทุกขั้นอีกครั้ง ถ้าผิดจะพากลับไปขั้นแรกที่มีปัญหา
- แถบขั้นตอนด้านบนกดย้อนไปขั้นที่ผ่านแล้วได้ ถ้าแก้จำนวนโปรเซส ขั้นที่ 2–3 จะล็อกจนกว่าจะกด "ถัดไป" ใหม่ (กันจำนวนช่อง BT ไม่ตรง)
- สีของโปรเซส: ช่อง `<input type="color">` ในขั้นที่ 2 ค่าเริ่มต้นเป็นชุดสี 20 สีที่ไม่ซ้ำกัน ใช้ใน Gantt chart, ตารางผลลัพธ์ และชุดข้อมูล
  สีตัวอักษรบนแถบ Gantt เลือกดำ/ขาวอัตโนมัติตามความสว่างของสีพื้น การเปลี่ยนสีไม่ทำให้ผลลัพธ์ถือว่า "ผลเก่า"
- ธีม: เพิ่มไฟล์ `js/theme.js` (โหลดใน `<head>` เพื่อไม่ให้จอกะพริบ) ถ้ายังไม่กดปุ่มจะใช้ธีมตามเครื่อง ถ้ากดจะจำค่าใน `localStorage`
  (ห่อด้วย try/catch ถ้า browser ปิด localStorage หน้าเว็บยังใช้ได้ แค่จำค่าไม่ได้)
**ไม่เปลี่ยน:** อัลกอริทึม, การตรวจ input, data contract — แก้เฉพาะ `index.html`, `css/style.css`, `js/ui.js` และเพิ่ม `js/theme.js`

### D-012 ภาษา TH/ENG, กล่องเลือกสีพร้อมสีตัวอย่าง, สวิตช์ธีมแบบสไลด์, สูตรของแต่ละค่า — ✅ (ผู้ใช้ขอ 2026-10-12)
**ปรับจาก D-010:** หน้าเว็บยังเป็นภาษาไทยเป็นค่าเริ่มต้น แต่กดปุ่ม **TH | ENG** มุมขวาบนเพื่อเปลี่ยนเป็นภาษาอังกฤษได้ (comment ในโค้ดยังเป็นภาษาไทย)
- ข้อความบนหน้าเว็บอยู่ใน `js/i18n.js` ที่เดียว (`TEXTS.th` / `TEXTS.en`) ข้อความคงที่ใน HTML ใช้ `data-i18n` ส่วนที่ ui.js สร้างใช้ `I18n.t()`
- ข้อความแจ้งเตือนอยู่ใน `js/validation.js` (`MESSAGES.th` / `MESSAGES.en`) ฟังก์ชันตรวจรับ `language` เป็นพารามิเตอร์ตัวสุดท้าย ไม่ส่ง = ภาษาไทย
  (ยังเป็น pure function — ไม่อ่านภาษาจากหน้าเว็บเอง test เดิมจึงผ่านโดยไม่ต้องแก้)
- จำภาษาที่เลือกไว้ใน `localStorage` เหมือนธีม ถ้าเปลี่ยนภาษาขณะมีข้อความเตือน กล่องเตือนจะซ่อน (ช่องที่ผิดยังเป็นสีแดง) กดปุ่มอีกครั้งจะได้ข้อความภาษาใหม่
- **กล่องเลือกสี:** ทำเองแทนการใช้ `<input type="color">` อย่างเดียว เพราะกล่อง RGB ของ browser ใส่สีตัวอย่างไม่ได้แน่นอนทุกเครื่อง
  กล่องมีสีตัวอย่าง 20 สี (ชุดเดียวกับสีเริ่มต้น) และช่อง "กำหนดเอง (RGB)" ที่เปิดกล่อง RGB ของ browser ปิดด้วย Esc หรือคลิกนอกกล่อง
- **สวิตช์ธีม:** `<button role="switch" aria-checked>` เลื่อนปุ่มกลมด้วย CSS (ปิด animation ถ้าเครื่องตั้ง reduce motion)
- **สูตรของแต่ละค่า:** ทุกแท็บอัลกอริทึมมีตาราง ค่า / ความหมาย / สูตร / แทนค่า ของ AT, BT, ST, CT, TAT, WT, AVG TAT, AVG WT
  เลือกโปรเซสที่จะแทนค่าได้ สูตร ST/CT ของ RR ต่างจาก FCFS/SJF (ดูจากช่วงแรก/ช่วงสุดท้ายใน Gantt) ตัวเลขทุกตัวมาจากผลของ Scheduler

### D-013 เปลี่ยนเป็น Dashboard หน้าเดียว ธีม Pixel Synthwave — ✅ (ผู้ใช้ขอ 2026-10-12)
> สีเริ่มต้น 20 สีของโปรเซส (นีออน/พาสเทล) ถูกแทนด้วยชุดสีสดใสใน **D-019**
> ชุดสี Pixel Synthwave (Neon Night / Pixel Sunrise) ถูกแทนด้วยชุดสี Cream / Ink ใน **D-016**
> ส่วน Layout (ส่วนหัวใหญ่ + 2 คอลัมน์ของการ์ด) ถูกแทนด้วย **D-014** — ชุดสี, การกด Run, KPI 4 ค่า, ฟอนต์ในเครื่อง ยังใช้ตามเดิม

ผู้ใช้ให้ปรับ Design ตาม prompt ออกแบบที่เตรียมมา (เฉพาะส่วน Design) และตอบคำถาม 4 ข้อ:
1. **Layout:** เปลี่ยนจากหน้าแบบทีละขั้น (**แทนส่วน "4 ขั้น" ของ D-011**) เป็น Dashboard 2 คอลัมน์
   ซ้าย = การ์ดตั้งค่าโปรเซส (ขั้นที่ 1+2 เดิม) / การ์ดอัลกอริทึม + Time Quantum (ขั้นที่ 3 เดิม) / การ์ดการจำลอง
   ขวา = Gantt chart / ค่าสรุป 4 ใบ / ตารางผลลัพธ์ / สูตร (พับได้) หรือหน้าเปรียบเทียบ
   จอแคบกว่า 1100px เป็นคอลัมน์เดียว (ตั้งค่าอยู่ก่อนผลลัพธ์)
   ส่วนอื่นของ D-011 ยังใช้เหมือนเดิม: สีของโปรเซส, สวิตช์ธีม, `theme.js` ใน `<head>`
2. **การคำนวณ:** ยังกดปุ่ม **Run** ตาม D-008 (snapshot ชุดเดียว, ข้อความเตือนผลเก่า, ประวัติ RR) ไม่คำนวณอัตโนมัติ
   การเลือก FCFS / SJF / RR หรือเปรียบเทียบ แค่สลับผลที่คำนวณไว้แล้ว
3. **ค่าสรุป (KPI) 4 ใบ:** ใช้ค่าที่ scheduler มีอยู่แล้ว — AVG WT, AVG TAT, เวลารวม (เวลาสิ้นสุดของช่วงสุดท้ายใน Gantt), จำนวนครั้งที่สลับโปรเซส (`countContextSwitches`)
   **ไม่เพิ่ม** Response Time / AVG CT / AVG RT จึงไม่ต้องแก้ `scheduler.js` และตารางยังเป็นคอลัมน์ตามโจทย์ (R1.4a)
4. **ฟอนต์:** ใช้ฟอนต์ที่มีในเครื่อง Windows (Segoe UI, Leelawadee UI, Cascadia Mono / Consolas) ไม่โหลดจากเน็ต ไม่แนบไฟล์ฟอนต์
   ลวดลายพิกเซล (ไอคอน, ดวงอาทิตย์, กริด, ดาว) วาดด้วย CSS / SVG ล้วน ไม่มีไฟล์ภาพ

รายละเอียดอื่น:
- จำนวนโปรเซสปรับด้วยการพิมพ์หรือปุ่ม − / + รายการโปรเซสเพิ่ม/ลดที่ท้ายรายการทันที แถวเดิมไม่ถูกสร้างใหม่ ค่า BT และสีจึงไม่หาย
  ถ้าพิมพ์ค่าผิด รายการเดิมยังอยู่ และจะแจ้งเตือนตอนกด Run (หน้าเว็บเริ่มที่ 4 โปรเซส สุ่ม BT)
- สีเริ่มต้น 20 สีเปลี่ยนเป็นชุดนีออน/พาสเทล (แถวแรกสีสด แถวสองสีอ่อน) และเลือกสีตัวอักษรบนแถบ Gantt ด้วยสูตร contrast ของ WCAG แทนสูตรความสว่างเดิม
- Gantt chart: แต่ละช่วงกว้างอย่างน้อย 44px ถ้าช่วงเยอะจะเลื่อนแนวนอนแทนการบีบ ชี้เมาส์/กด Tab ที่แถบเพื่อดูเวลาเริ่ม/สิ้นสุด/ระยะเวลา
- ไม่ทำปุ่มเล่น Timeline (Start / Pause / Step) เพราะเป็นฟีเจอร์ใหม่ ไม่ใช่งาน Design และห้ามมีปุ่มที่กดแล้วไม่มีผลจริง
- Animation ทั้งหมดปิดเมื่อเครื่องตั้งค่า "ลดการเคลื่อนไหว" (`prefers-reduced-motion`)
**ไม่เปลี่ยน:** `scheduler.js`, `validation.js`, data contract, test

### D-014 แถบ CPU หลายตัว (เหมือนโปรไฟล์) + Layout ใหม่แบบหน้าต่างระบบปฏิบัติการยุคพิกเซล — ✅ (ผู้ใช้ขอ 2026-10-12)
> หน้าตาแบบหน้าต่างยุคพิกเซลถูกแทนด้วย Minimal Luxury ใน **D-016** — ฟีเจอร์ CPU หลายตัว (ข้อมูล, การบันทึก, ขีดจำกัด 12 ตัว) ยังใช้ตามเดิม
ผู้ใช้ขอ 2 เรื่อง: (1) เพิ่มแท็บด้านซ้ายที่สร้าง CPU ได้หลายตัว เลือกและสลับไปมาได้เหมือนโปรไฟล์
(2) ออกแบบ Layout ใหม่ เพราะหน้าตาตาม D-013 คล้ายเว็บตัวอย่าง smartcpuscheduler.com เกินไป แต่ **ให้คงสีและโทนเดิม** (Pixel Sunrise / Neon Night)

**แทนส่วน Layout ของ D-013** (ส่วนหัวใหญ่กลางจอ + Dashboard 2 คอลัมน์ของการ์ด) ด้วยโครงหน้าใหม่:
- **แถบ CPU ด้านซ้าย** (กว้าง 272px ติดอยู่กับที่ขณะเลื่อนหน้า): ชื่อโปรแกรม, รายการ CPU, ปุ่ม "+ เพิ่ม CPU", ฉากดวงอาทิตย์ + กริดเล็ก ๆ ท้ายแถบ
  แต่ละรายการแสดงชื่อ, จำนวนโปรเซส, TQ, จุดสถานะ (ยังไม่ Run / Run แล้ว / ผลเก่า) และแท่งเล็ก ๆ แทน BT ของแต่ละโปรเซส (สีตามโปรเซส)
- **หัวพื้นที่ทำงาน** (ติดด้านบนขณะเลื่อน): ชื่อ CPU ตัวใหญ่ + ป้ายสถานะ, ปุ่มเปลี่ยนชื่อ / ทำสำเนา / ลบ, ปุ่มภาษาและสวิตช์ธีม
- **หน้าต่างโปรเซส** (ฟอร์มเดียว Enter = Run): จำนวนโปรเซส + วิธีกำหนด BT → การ์ดโปรเซสเรียงเป็นตาราง (แถบสีด้านบนกดเพื่อเลือกสี) → แถบท้ายหน้าต่างมี TQ + ปุ่ม Run

- หน้าตา: กล่องเป็น "หน้าต่าง" มีแถบหัว + จุดสี่เหลี่ยม 3 สี, มุมเหลี่ยมเล็กน้อย, **เงาแข็งเยื้องขวาล่าง** แบบเกมพิกเซล, ค่าสรุปเป็นแบบจอตัวเลข (LCD) แทนการ์ดไล่สี
  ชุดสีทั้งสองธีมเหมือนเดิม เพิ่มเฉพาะตัวแปรของส่วนใหม่ (`--rail-bg`, `--window-bar-bg`, `--hard-shadow`, `--kpi-*` ฯลฯ)
- จอแคบกว่า 900px: แถบ CPU ย้ายไปด้านบน รายการ CPU เลื่อนแนวนอน

### D-015 ฉากดวงอาทิตย์เป็นพื้นหลังแถบ CPU + ลดความลายตา ให้ดูเป็นหน้าหลักมากขึ้น — ✅ (ผู้ใช้ขอ 2026-10-12)

  เส้นขอบฟ้าอยู่ที่ 30% จากขอบล่างของจอ ดวงอาทิตย์อยู่กลางพื้นที่ทำงาน (เลื่อนไปทางขวาครึ่งหนึ่งของแถบซ้าย)
  แถบซ้ายและหน้าต่างหลักมีพื้นโปร่งแสงเล็กน้อยให้เห็นฉากด้านหลัง ส่วนกล่องย่อย (ตาราง, Gantt, ค่าสรุป) ยังเป็นพื้นทึบเพื่อให้อ่านง่าย
  ปุ่ม CPU มีพื้นโปร่งแสงเล็กน้อย ชื่อโปรแกรมในแถบซ้ายเหลือแค่โลโก้ "CPU SIM"
  จอแคบกว่า 900px: ดวงอาทิตย์อยู่กลางจอ วางต่ำลงและจางลง เพราะข้อความทับฉากมากกว่า
- **ส่วนหัวหน้าหลัก** ที่ต้นพื้นที่ทำงาน: ป้าย "OS Term Project" + ชื่อโปรแกรมตัวใหญ่ชิดซ้าย + คำอธิบาย 1 บรรทัด ปุ่มภาษา/ธีมมุมขวา

  เงาแข็งเหลือเฉพาะหน้าต่างหลัก ปุ่ม Run และ CPU ที่เลือก

### D-016 Minimal Luxury Redesign ตาม prompt ใหม่จาก GPT — ✅ (ผู้ใช้ขอ 2026-10-12)
> โครงหน้า (เมนูนำทาง 5 รายการ, การ์ดโปรเซสในพื้นที่หลัก, ลิ้นชักบนมือถือ) ถูกแทนด้วย **D-017** — ชุดสี, หัวข้อกึ่งกลาง, พื้นหลัง, การ์ด CPU แบบ 3D และ popup ยังใช้ตามเดิม
ผู้ใช้ส่ง prompt "CPU Scheduling Simulator — Minimal Luxury Dashboard Redesign" (รีดีไซน์ UI ทั้งระบบ ห้ามแตะ logic) แล้วตอบคำถาม 4 ข้อ:
1. **ชุดสี:** ใช้ชุดสีใหม่ตาม prompt (**แทนชุดสี Pixel Synthwave ของ D-013**) — ธีมสว่าง "Cream" (ครีม/เบจ + คอรัล + ลาเวนเดอร์หม่น + ทองแชมเปญ, ตัวอักษรน้ำเงินหมึก) และธีมมืด "Ink" (น้ำเงินเข้มหม่น) ยังสลับธีมได้เหมือนเดิม
2. **หัวข้อหลัก:** กึ่งกลางบนตาม prompt ตัวอักษรไล่สี หมึก → ม่วง → คอรัล → ทอง (ภาษา/ธีมมุมขวาบน)
3. **พื้นหลัง:** คงดวงอาทิตย์แต่เป็นแบบไล่สีนุ่มจาง ๆ ไม่มีแถบ/กริด/ดาว (**แทนฉาก Synthwave ของ D-015**)
4. **Popup:** ผู้ใช้ให้ AI แนะนำ → ทำ 3 แบบ: รายละเอียด/จัดการ CPU, วิธีทำงานของอัลกอริทึม, ตั้งค่า (ไม่ทำ popup ของช่วงใน Gantt เพราะมี tooltip แล้ว)

**โครงหน้าและชั้น** (จากหลังไปหน้า): พื้นหลัง → พื้นผิวหลัก (`.surface`) → แถบเมนูซ้าย + การ์ดเนื้อหา → popup
- **แถบเมนูซ้าย** สีน้ำเงินเข้ม (ธีมสว่างเปลี่ยนเป็นสีอ่อนใน D-031) ลอยแยกจากเนื้อหา (มุมโค้ง เงานุ่ม): โลโก้, เมนู 5 รายการ, รายการ CPU, ปุ่มเพิ่ม CPU
  เมนูทุกรายการทำงานจริง: ภาพรวม / ตั้งค่าการจำลอง / ผลการจำลอง = เลื่อนหน้าไปยังส่วนนั้น (ไฮไลต์ตามส่วนที่กำลังดู), เปรียบเทียบ = เปิดหน้าเปรียบเทียบ (กดได้หลัง Run), ตั้งค่า = เปิด popup
- **การ์ด CPU แบบ 3D ลอย:** ขอบบนสว่าง + เงาใต้การ์ด, ชี้เมาส์แล้วยกขึ้น, ตัวที่เลือกเป็นแผ่นสีครีมลอยเด่นพร้อมเงาสีประจำ CPU, ปุ่ม ⋯ เปิด popup รายละเอียด
- **การ์ดเนื้อหา:** การ์ดโปรเซส (ขั้นที่ 1) → หัวผลลัพธ์ + แท็บแบบเม็ดยา (FCFS / SJF / RR / เปรียบเทียบ) → แถบคำอธิบายสั้น + ปุ่ม "วิธีทำงาน" → Gantt → ค่าสรุป 4 ช่อง → ตาราง → สูตร (accordion)
  รายละเอียดประเภท / จุดเด่น / ข้อจำกัดของอัลกอริทึมย้ายไปอยู่ใน popup "วิธีทำงาน" เพื่อลดความรกของหน้าหลัก
- **Popup:** ใช้ `<dialog>` ของ browser (Esc ปิดได้, โฟกัสอยู่ใน popup, คลิกพื้นหลังปิดได้) โค้ดอยู่ในไฟล์ใหม่ `js/modals.js`
  ภาพประกอบวาดเป็น SVG จากข้อมูลจริง: กราฟแท่ง BT ของ CPU, ลำดับคิว → CPU และ Gantt ย่อจากผล Scheduler
  ถ้า CPU ยังไม่ได้ Run ภาพ "วิธีทำงาน" ใช้ข้อมูลตัวอย่าง TC-01 ที่ Scheduler คำนวณจริง และเขียนบอกไว้ใต้ภาพ (ไม่ใช่ข้อมูลปลอม)
- **ลบ / ล้างข้อมูล** ยืนยันด้วยกล่องในตัว popup แทน `window.confirm`; เปลี่ยนชื่อ / ทำสำเนา / ลบ ย้ายจากปุ่มบนหัวมาอยู่ใน popup รายละเอียด CPU
- **จอแคบกว่า 1024px:** แถบเมนูซ้ายเป็นลิ้นชัก เปิดด้วยปุ่ม ☰ ปิดด้วย ✕ / Esc / คลิกพื้นหลัง / เลือก CPU
- **ตัวอักษร:** ยังใช้ฟอนต์ในเครื่องตาม D-013 (Segoe UI Variable Display/Text + Leelawadee UI) — ไม่มีฟอนต์พิกเซล ไอคอนพิกเซลเปลี่ยนเป็นไอคอนเส้น
- **การเข้าถึง:** กรอบโฟกัสชัดทุกปุ่ม, คู่สีตัวอักษร/พื้นหลักทุกคู่ contrast ≥ 4.5:1 (ตรวจด้วยสูตร WCAG), Animation ปิดเมื่อเครื่องตั้ง "ลดการเคลื่อนไหว"
**ไม่เปลี่ยน:** `scheduler.js`, `validation.js`, `profiles.js` (ยกเว้นค่าเริ่มต้นสูตรพับไว้จาก D-015), data contract, test, ฟีเจอร์เดิมทั้งหมด

  การ์ดที่กางกับแผงตั้งค่าต่อกันเป็นแผ่นสีครีมแผ่นเดียว แถบซ้ายกว้างขึ้นเป็น 372px เพื่อให้แผงตั้งค่ามีที่พอ (D-022: กว้าง 420px และเลิกแถบเลื่อนในตัว)
- **แผงตั้งค่า** มีชุดเดียว (`#cpu-panel` ฟอร์มเดิม) ui.js ย้ายไปไว้ใต้การ์ดของ CPU ที่เลือก เนื้อหา: จำนวนโปรเซส + TQ → วิธีกำหนด BT → การ์ดโปรเซส → สุ่มใหม่ / สีเริ่มต้น → Run / ข้อมูลตัวอย่าง
  ระหว่างพิมพ์ในแผง ui.js อัปเดตเฉพาะการ์ดของ CPU ที่เลือก (`updateActiveCpuCard`) ไม่วาดรายการใหม่ทั้งหมด เพราะการย้ายแผงทำให้ช่องที่กำลังพิมพ์หลุดโฟกัส
- **ตรงกลาง:** ส่วนหัวชื่อโปรแกรม แล้วพื้นผิวผลลัพธ์ (ชื่อ CPU + สถานะ + แท็บ + ปุ่ม ⋯ จัดการ CPU → คำอธิบายอัลกอริทึม → Gantt → ค่าสรุป → ตาราง → สูตร)
- **ปุ่มตั้งค่า** ย้ายจากเมนูซ้ายไปเป็นไอคอน ⚙ มุมขวาบน ข้างปุ่มภาษาและธีม
- **จอแคบกว่า 1024px:** เลิกใช้ลิ้นชัก เรียงเป็นคอลัมน์เดียว ชื่อโปรแกรม → แถบ CPU (พร้อมแผงตั้งค่า) → ผลลัพธ์
- **ต่างจากเว็บตัวอย่าง:** เว็บตัวอย่างเป็นการ์ดตารางโปรเซสวางคู่การ์ด Gantt แบบตายตัว ของเราเป็นการ์ด CPU หลายตัวบนแถบสีเข้มที่กางเป็น dropdown ทีละตัว และใช้ชุดสี/ตัวอักษรคนละแบบ
**ไม่เปลี่ยน:** logic ทั้งหมด, ฟีเจอร์เดิม, popup 3 แบบ, ชุดสี

### D-018 แถวโปรเซสกะทัดรัด, กางการตั้งค่าด้วยปุ่มลูกศร, ลบปุ่มข้อมูลตัวอย่าง, คำอธิบายใต้หัวข้อเหลือแค่ชื่ออัลกอริทึม — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้ส่งภาพหน้าจอประกอบ 5 ข้อ:
1. **การ์ดโปรเซสใหญ่เกิน** ถ้ามีหลายรายการปรับยาก → เปลี่ยนเป็น **แถวเล็ก 2 คอลัมน์**: จุดสีกลม (กดเปลี่ยนสี) | ชื่อ | ช่อง BT และเส้นซ้ายสีของโปรเซส
   ไม่แสดง "AT 0" ซ้ำทุกแถว (มีป้าย AT = 0 ที่หัวแผงแล้ว) — 20 โปรเซสสูงประมาณ 480px (การ์ดแบบเดิมประมาณ 1,400px)
2. **ลบปุ่ม "ใช้ข้อมูลตัวอย่าง"** (ยกเลิกส่วนนี้ของ D-009) — ข้อมูล TC-01 ในโค้ดยังใช้วาดภาพใน popup "วิธีทำงาน" ตอน CPU ยังไม่ได้ Run
3. **กดการ์ด CPU = เลือกอย่างเดียว** ไม่กางการตั้งค่า / กาง-พับด้วย **ปุ่มลูกศรมุมขวาล่างของการ์ด** (`aria-expanded`)
   กดลูกศรของ CPU ตัวอื่น = เลือกและกางเลย / เพิ่ม CPU ใหม่ = กางให้เลย (ต้องตั้งค่าก่อน) / เปิดหน้าเว็บ = กางการตั้งค่าของ CPU ที่เลือกไว้
4. **หางตัวอักษรของหัวข้อหลักถูกตัด** (g ใน Scheduling) — ตัวอักษรไล่สีวาดเฉพาะในกรอบของหัวข้อ → line-height 1.2 + เว้นด้านล่างเล็กน้อย
5. **คำอธิบายใต้หัวข้อ** เหลือแค่ "FCFS · SJF · Round Robin" (เหมือนกันทั้งสองภาษา ไม่มีภาษาไทยยาว ๆ)
เพิ่มเติม: ข้อความปุ่ม Run สั้นลงเป็น "Run ทั้ง 3 อัลกอริทึม" เพราะในแผงแคบบนมือถือข้อความเดิมตัดบรรทัดกลางคำ

### D-019 ชุดสีโปรเซสแบบสดใส (Vibrant) + มิติด้วย gradient / แสงเรือง — ✅ (ผู้ใช้ขอ 2026-10-12)
> สีเริ่มต้นของโปรเซส ความฟุ้ง และสีตัวอักษรบน Gantt ถูกปรับใน **D-020** — สีค่าสรุป 4 ช่องและกราฟเปรียบเทียบยังใช้ตามเดิม
ผู้ใช้ส่ง prompt ปรับสีโปรเซสและกล่องเลือกสีให้สด คมชัด ไม่ซีดแบบ pastel (ส้ม ม่วง เขียว ฟ้า แบบภาพ Performance Metrics — ไม่ได้แนบภาพ AI ทำตามสีที่ระบุ)
**แทนชุดสีเริ่มต้น 20 สีของ D-013** (เฉพาะสีของโปรเซส ชุดสีของหน้าเว็บ D-016 ไม่เปลี่ยน):
- แถวแรก 10 สีสด: ส้ม #FF8500, ม่วง #8545FF, เขียวมรกต #00C49A, ฟ้า #008FFF, ชมพู #FF438C, เหลือง #FFD43B, ฟ้าอมเขียว #00C8E8, แดง #FF4D4D, คราม #4F46E5, เขียวมะนาว #84CC16
- แถวสอง 10 สี = สีเดียวกันโทนเข้ม (ยังสด แยกจากแถวแรกด้วยความเข้ม) — กล่องเลือกสีใช้ 20 สีนี้ และยังมี "กำหนดเอง (RGB)"
- ตัวอักษรบนแถบสียังเลือกดำ/ขาวอัตโนมัติ (`textColorOn`) ทุกสีได้ contrast ≥ 4.89:1
**มิติ:** แถบ Gantt มีแสงสะท้อนด้านบน + แสงเรืองสีของโปรเซสใต้แถบ, แถวโปรเซสพื้นอมสีจาง ๆ + เส้นซ้ายสี + จุดสีมีแสงเรือง, จุดสีใน legend / tooltip เป็นวงกลมมีแสงสะท้อน
**ตาราง:** ใช้สีเป็นจุดสี + แถบสีซ้ายของช่องชื่อโปรเซส ไม่ลงสีทั้งแถว
**ค่าสรุป 4 ช่อง** ใช้ ส้ม / ม่วง / เขียวมรกต / ฟ้า: กล่องไอคอนไล่สี + เส้นบนไล่สี + พื้นการ์ดอมสีจาง ๆ ที่มุม (ตัวเลขยังเป็นสีตัวอักษรปกติ อ่านง่าย) กราฟเปรียบเทียบใช้ ส้ม→ชมพู (WT) และ ม่วง→ฟ้า (TAT)
ui.js เปลี่ยนเฉพาะรายการสีเริ่มต้น และส่งสีให้ CSS ผ่านตัวแปร `--process-color` (ใช้ทำแสงเรือง) — **ไม่แตะ logic**
ใช้ `color-mix()` ของ CSS (Chrome / Edge 111 ขึ้นไป) ทำพื้นอมสีจาง ๆ

### D-020 สีโปรเซสโทน jewel ที่เข้ากับเว็บ, ลดความฟุ้ง, ตัวอักษรบน Gantt สีขาวเสมอ — ✅ (ผู้ใช้ขอ 2026-10-12)
> ชุดสีเริ่มต้นและความเรืองของ Gantt ถูกปรับอีกครั้งใน **D-021** (สดขึ้น) — ตัวอักษรขาวและเกณฑ์ contrast ยังใช้ตามเดิม
ผู้ใช้: แถบ Gantt และแถวตั้งค่าโปรเซส "ฟุ้งเกิน", สีเริ่มต้นเด่นเกินไป อยากให้เข้ากับเว็บมากกว่านี้ (ส่วนอื่นดีแล้ว) และให้ตัวอักษรใน Gantt เป็นสีขาวอย่างเดียว
- **สีเริ่มต้น 20 สี (แทน D-019):** โทน jewel ที่เข้ากับคอรัล / ลาเวนเดอร์ / ทอง / หมึกของเว็บ — แถวแรก ส้มอิฐ #C4512B, ม่วง #7454D6, เขียว #11805F, ฟ้า #2C66CC, ชมพูกุหลาบ #C63D72, ทอง #946812, ฟ้าอมเขียว #177F8F, แดง #C0403A, คราม #4D45BF, เขียวมะกอก #557F1C / แถวสอง = สีเดียวกันโทนเข้ม
  เพราะตัวอักษรเป็นสีขาวเสมอ ทุกสีจึงต้องเข้มพอ: contrast กับสีขาว ≥ 4.6:1 (สีสว่างอย่างเหลือง/เขียวมะนาวของ D-019 จึงถูกเอาออก)
- **ตัวอักษรบน Gantt (และภาพคิว / Gantt ย่อใน popup) เป็นสีขาวเสมอ** + เงาตัวอักษรบาง ๆ ช่วยกรณีผู้ใช้เลือกสีอ่อนเอง
  เลิกใช้ฟังก์ชันเลือกสีตัวอักษรอัตโนมัติ (`textColorOn`, `relativeLuminance`) จึงลบออกจาก ui.js
- **ลดความฟุ้ง:** แถบ Gantt เหลือเงานุ่มสีเดียวกันแบบแคบและจาง (เดิมเป็นแสงเรืองกว้าง), แถวโปรเซสเลิกใช้แสงเรือง พื้นอมสีเหลือ 8% (เดิม 14%), จุดสี / สีตัวอย่าง / แท่งเล็กเหลือแค่แสงสะท้อนบาง ๆ
- **ไม่เปลี่ยน:** สีค่าสรุป 4 ช่อง (ส้ม / ม่วง / เขียว / ฟ้า แบบสด) และกราฟเปรียบเทียบ — ผู้ใช้บอกว่าส่วนอื่นดีแล้ว, logic ทั้งหมด

### D-021 สีโปรเซสสดขึ้น (ไม่ตุ่น) แต่ยังอยู่ในธีม + Gantt เรืองขึ้นเล็กน้อย — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้: สีของ D-020 "ดูตุ่น ๆ" อยากให้สดใสกว่านี้แต่ไม่หลุดธีม และเพิ่มความฟุ้งของ Gantt ขึ้นนิดหนึ่ง
- **วิธีเลือกสี:** ทุกเฉดใช้ saturation สูง (65–90%) แล้วเลือก "ความสว่างสูงสุดที่ตัวอักษรขาวยังได้ contrast ≥ 4.6:1" จึงสดที่สุดเท่าที่ตัวขาวยังอ่านง่าย (สีของ D-020 ตุ่นเพราะ saturation ต่ำ)
  ไม่ใช้ saturation 100% เพราะลองแล้วแดง/ชมพูจัดจ้านเกินธีม
- **แถวแรก:** ส้ม #C54F14, ม่วง #8255EC, เขียวมรกต #078564, ฟ้า #1370EA, ชมพูกุหลาบ #DF2066, บานเย็น #BD2DDA, ฟ้าอมเขียว #087E9B, แดง #DD2F3A, คราม #6363E6, เขียว #20871D
  **แถวสอง:** สีเดียวกันเข้มลง 8% (contrast 5.9–7.7:1)
  เปลี่ยนสีทองเป็นบานเย็น เพราะเฉดเหลือง/ทองที่เข้มพอสำหรับตัวขาวจะกลายเป็นสีน้ำตาลตุ่น
- **Gantt:** แสงเรืองใต้แถบกว้างและเข้มขึ้นเล็กน้อย (0 9px 18px สีของโปรเซส 75%, ตอนชี้เมาส์ 0 13px 24px) แสงสะท้อนด้านบน 20% — แถวตั้งค่าโปรเซสยังไม่มีแสงเรืองตาม D-020

### D-022 ลำดับการได้ CPU เป็นเม็ดสี, ค่าสรุปมีกราฟจิ๋วแทนที่มาของค่า, แถบซ้ายกว้างขึ้นและไม่มีแถบเลื่อนของตัวเอง — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้: (1) เอาข้อความ "ลำดับการได้ CPU: P1 → P2 → …" ออก ให้เม็ดสี (P1 BT 2 …) เป็นลำดับแทน (2) เอาข้อความ (0 + 2 + …) ใต้ค่าสรุปออกทั้ง 4 ช่อง และให้กล่องไม่โล่ง
(3) แถบซ้ายใหญ่ขึ้น (4) กาง dropdown แล้วการ์ดเหมือนถูกบีบด้วยแถบเลื่อน (5) กล่องเลือกสีติดอยู่กับหน้าหลัก ไม่เลื่อนตามแถบซ้าย
- **ลำดับการได้ CPU:** เม็ดสีเรียงตาม Gantt chart มีลูกศร › คั่น (`<ol>`) — FCFS/SJF แสดง "BT n" (รันครั้งเดียวจนเสร็จ), RR มีเม็ดซ้ำได้และแสดง "รัน n" (เวลาที่ใช้ในรอบนั้น) ปิดท้ายด้วย "รวม BT" เหมือนเดิม
  legend สีแยก (P1..Pn) ถูกรวมเข้าไปในเม็ดลำดับนี้ เพราะเม็ดก็บอกสีของแต่ละโปรเซสอยู่แล้ว
- **ค่าสรุป 4 ช่อง:** เอาข้อความใต้ตัวเลขออก (ที่มาของค่าเฉลี่ยยังอยู่ในส่วน "สูตรการคำนวณ") แถวล่างเป็นตัวเลขทางซ้าย + กราฟจิ๋วสีของโปรเซสทางขวา:
  AVG WT / AVG TAT / เวลารวม = แท่งของแต่ละโปรเซสสูงตาม WT / TAT / CT, สลับโปรเซส = แถบ Gantt จิ๋ว (สีเปลี่ยน = สลับหนึ่งครั้ง)
  กราฟเป็นภาพประกอบ (`aria-hidden`) ใช้ค่าจาก result ที่ scheduler คำนวณแล้ว ไม่ได้คำนวณใหม่
- **แถบซ้าย:** กว้าง 372 → 420px และสูงตามเนื้อหา เลื่อนไปพร้อมหน้าเว็บ (เลิก sticky + แถบเลื่อนในตัว ซึ่งกินที่จนการ์ดที่กางดูถูกบีบ) — **ถูกแทนด้วย D-024** (ผู้ใช้อยากให้แถบซ้ายเลื่อนแยกจากหน้า)
- **กล่องเลือกสี:** ย้ายจากท้าย `<body>` ไปอยู่ใน `#cpu-panel` (นอก `<form>` เหมือนเดิม) และวางตำแหน่งโดยนับจากมุมของแผง จึงเลื่อนไปพร้อมแถบซ้ายเสมอ — **ถูกแทนด้วย D-024**

### D-023 ตัวอักษรใหญ่ขึ้นทั้งหน้า (ฐาน 17px) และตัวเล็กสุดไม่ต่ำกว่า ~14px — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้: ขยายตัวอักษรให้ใหญ่และอ่านง่ายกว่านี้
- `html { font-size: 106.25% }` = ฐาน 17px (เดิม 16px) ขนาดทุกตัวใน style.css เป็น rem จึงใหญ่ขึ้นตามกันทั้งหน้า ใช้ % เพื่อให้ยังขยายตามที่ผู้ใช้ตั้งใน browser ได้
- ตัวอักษรเล็กที่สุด (คำอธิบายใต้ช่อง ป้าย ชื่อเต็มในค่าสรุป) เดิม 0.72–0.82rem (≈ 11.5–13px) ยกเป็น 0.82–0.86rem (≈ 14–14.6px) เพราะภาษาไทยตัวเล็กอ่านยาก
- เผื่อที่ใต้ Gantt ให้ตัวเลขเวลาที่ใหญ่ขึ้น (padding ล่าง 44px + `overflow-y: hidden` กันแถบเลื่อนแนวตั้งโผล่)
- ไม่เปลี่ยนตัวอักษรในภาพ SVG ของ popup (ขนาดอิงกรอบภาพ ซึ่งย่อขยายตามความกว้างอยู่แล้ว)

### D-024 แถบซ้ายค้างอยู่กับที่ และรายการ CPU เลื่อนขึ้นลงแยกจากหน้า (แทนส่วนแถบซ้ายของ D-022) — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้: สร้าง CPU ใหม่แล้วเลื่อน กลายเป็นเลื่อนทั้งหน้า อยากให้เลื่อนขึ้นลงเฉพาะแถบซ้าย
- **แถบซ้าย:** กลับเป็น sticky สูงเต็มจอ โลโก้ด้านบนและปุ่ม "เพิ่ม CPU" ด้านล่างอยู่กับที่ รายการ CPU (รวมแผงตั้งค่าที่กาง) เลื่อนได้ในแถบเอง
  `overscroll-behavior: contain` = เลื่อนสุดรายการแล้วไม่ไหลไปเลื่อนทั้งหน้าต่อ
- **ไม่ให้การ์ดถูกบีบอีก (ปัญหาเดิมของ D-022):** แถบเลื่อนแบบบางวางในขอบว่างด้านขวาของแถบ (margin ติดลบ) และจองที่ไว้ตลอด (`scrollbar-gutter: stable`) การ์ดจึงกว้าง 384px เท่ากันไม่ว่าแถบเลื่อนจะโผล่หรือไม่
- **สร้าง CPU ใหม่:** รายการเลื่อนให้การ์ดใหม่อยู่บนสุดของแถบ (`scrollCpuListTo`) โดยไม่เลื่อนทั้งหน้า
- **กล่องเลือกสี:** ย้ายกลับไปท้าย `<body>` เป็น `position: fixed` (ถ้าอยู่ในรายการที่เลื่อนได้ กล่องจะถูกตัดขอบ เพราะกล่องกว้างเกินแถบ)
  ui.js ขยับกล่องตามจุดสีทุกครั้งที่รายการหรือหน้าเลื่อน ถ้าจุดสีเลื่อนพ้นส่วนที่มองเห็นให้ปิดกล่อง และถ้าด้านล่างไม่พอให้วางกล่องเหนือจุดสี
- **จอแคบกว่า 1024px:** เหมือนเดิม (คอลัมน์เดียว แถบ CPU เลื่อนไปพร้อมหน้า)

### D-026 ภาพชิป CPU แบบเส้นหมุนจาง ๆ ในพื้นหลัง + แถบซ้ายและพื้นผิวผลลัพธ์โปร่งนิดหน่อย — ✅ (ผู้ใช้ขอ 2026-10-12)
ผู้ใช้: อยากให้พื้นหลังมีลูกเล่น เช่น CPU สไตล์ Art จาง ๆ หมุนอยู่ด้านหลัง ให้ดูมีชีวิตชีวา และให้กล่องแถบซ้ายกับตรงกลางโปร่งนิดหน่อยให้เห็นพื้นหลัง แต่ไม่ลายตา

- **ปรับรอบสอง (ผู้ใช้ขอให้มีชิปหมุนที่แถบซ้ายด้วย และโปร่งขึ้นอีก):**

### D-027 ภาพชิปฝั่งซ้ายอยู่ชั้นพื้นหลังหลังสุด + แท็บอัลกอริทึมและปุ่ม ⋯ เด่นขึ้น — ✅ (ผู้ใช้ขอ 2026-10-12)

### D-039 หน้าเปรียบเทียบ CPU (เทียบผลหลายชุดข้อมูล) — ✅ (ผู้ใช้ขอ 2026-10-13)
ผู้ใช้: ฟีเจอร์ Compare ระหว่าง CPU → ให้ทำตามที่ AI แนะนำ
เหตุผล: R2f ให้แสดง "เปรียบเทียบเมื่อเปลี่ยน **BT** หรือ TQ" — ฝั่ง TQ มีตารางประวัติ RR แล้ว แต่ฝั่ง BT ยังเทียบในจอเดียวไม่ได้
(D-008 ล้างประวัติเมื่อชุด BT เปลี่ยน) วิธีใช้ในวิดีโอ: ทำสำเนา CPU → แก้ BT (หรือ TQ) ของสำเนา → Run → เปิดหน้าเปรียบเทียบ CPU
- **ปุ่ม "เปรียบเทียบ CPU"** ในแถบซ้าย ใต้ปุ่ม "เพิ่ม CPU" กดแล้วพื้นที่ตรงกลางเปลี่ยนเป็นหน้าเปรียบเทียบ (แทนผลของ CPU ที่เลือก)
  ปิดได้ด้วยปุ่มเดิม, ปุ่ม × บนหัวหน้า, หรือกดการ์ด CPU ใดก็ได้ (= กลับไปดูผลของ CPU นั้น)
  สีปุ่ม (ผู้ใช้ขอ 2026-10-13): ยังไม่เปิด = ไล่สีคอรัล / เปิดอยู่ = พื้นเรียบไม่มีสี (สลับจากที่ AI ทำครั้งแรก)
- เนื้อหา: (1) checkbox เลือก CPU — เลือกได้เฉพาะตัวที่ Run แล้ว ค่าเริ่มต้น = ทุกตัวที่ Run แล้ว
  (2) กราฟแท่งจัดกลุ่มตาม CPU กลุ่มละ 3 แท่ง FCFS / SJF / RR **สเกลเดียวกันทั้งกราฟ** จึงเทียบข้าม CPU ได้ แท่งที่ต่ำสุดในแต่ละ CPU มีป้าย "ต่ำสุด"
  (3) ตาราง CPU | ชุด BT | TQ | FCFS | SJF | RR ช่องที่ต่ำสุดของแต่ละ CPU ไฮไลต์ กดชื่อ CPU = เปิดผลของ CPU นั้น
  ต้องเลือกอย่างน้อย 2 ตัว ไม่อย่างนั้นแสดงคำแนะนำวิธีสร้างชุดข้อมูลไว้เทียบ (ทำสำเนา → แก้ → Run)
- **ค่าที่เทียบ:** แท็บสลับ AVG WT (ค่าเริ่มต้น ตรงกับ R1.4d) / AVG TAT — ใช้กับทั้งกราฟและตาราง
- **ตัวเลขมาจากผล Run ล่าสุดของแต่ละ CPU** (`profile.results` + `profile.burstTimes`) ไม่ใช่ค่าที่อยู่ในช่องกรอก
  CPU ที่แก้ข้อมูลหลัง Run ติดป้าย "ผลเก่า" และมีหมายเหตุให้กด Run ใหม่ — ช่อง BT ในตารางจึงตรงกับตัวเลขเสมอ
- หน้าเปรียบเทียบอัปเดตทันทีเมื่อ Run / แก้ข้อมูล / เพิ่ม / ทำสำเนา / ลบ / เปลี่ยนชื่อ CPU / เปลี่ยนภาษา
- โค้ดอยู่ในไฟล์ใหม่ `js/compare.js` (โหลดหลัง modals.js ก่อน ui.js — แบบเดียวกับ modals.js) ไม่แตะ DOM ส่วนอื่น ไม่คำนวณผลเอง
  หาค่าต่ำสุดเพื่อไฮไลต์เท่านั้น (เหมือน `lowestOf` ในหน้าเปรียบเทียบอัลกอริทึม)
- หมายเหตุใต้ตาราง: เมื่อ AT = 0 SJF ได้ค่าต่ำสุด (หรือเท่ากับต่ำสุด) เสมอ — มี invariant ใน `tests/scheduler.test.js` รองรับอยู่แล้ว
**รายละเอียดที่ AI เลือกเอง — 🟦 รอผู้ใช้ยืนยัน:** ไม่จำว่าเปิดหน้าเปรียบเทียบค้างไว้ (เปิดเว็บใหม่จะเห็นผลของ CPU ที่เลือก),
ไม่จำ checkbox ที่เอาออก (เปิดเว็บใหม่จะเลือกทุกตัวที่ Run แล้ว), สีแท่ง FCFS ส้ม-ชมพู / SJF ม่วง-ฟ้า / RR เขียว-ฟ้าอมเขียว
**ไม่เปลี่ยน:** `scheduler.js`, `validation.js`, `profiles.js`, data contract, หน้าเปรียบเทียบ 3 อัลกอริทึมเดิม (แท็บ "เปรียบเทียบ")

- ไอคอนปุ่มตั้งค่า: เปลี่ยนจากวงกลม + เส้นรอบ ๆ (ดูคล้ายไอคอนดวงอาทิตย์ของสวิตช์ธีมที่อยู่ข้างกัน) เป็น **แถบเลื่อนปรับค่า 3 เส้น**
- ลบข้อความ `settingsLanguage*` / `settingsTheme*` ที่ไม่ได้ใช้แล้วออกจาก i18n.js ทั้ง TH / EN

### D-041 สวิตช์ปิด animation พื้นหลังในหน้าตั้งค่า — ✅ (ผู้ใช้ขอ 2026-10-13)
ผู้ใช้ถามว่าควรมีอะไรในหน้าตั้งค่า → AI แนะนำ 3 อย่าง (ปิด animation / ส่งออก-นำเข้าข้อมูล / เกี่ยวกับโปรแกรม) → ผู้ใช้: "เอาปิด Animation มาก่อน"
เหตุผล: ตอนอัดวิดีโอ พื้นหลังที่ขยับดึงสายตาและทำให้ไฟล์วิดีโอแตกเป็นบล็อก เดิมปิดได้ทางเดียวคือตั้ง "ลดการเคลื่อนไหว" ใน Windows
- popup ตั้งค่ามี 2 แถว: **Animation พื้นหลัง** (สวิตช์ เปิดเป็นค่าเริ่มต้น) → ล้างข้อมูล CPU
- ปิดแล้วหยุดเฉพาะของตกแต่งพื้นหลัง: ดวงอาทิตย์ที่ขยาย/หด, แสงส้ม 2 ดวง, ภาพชิป 2 ภาพ + วงแหวนที่หมุน — หยุดที่ท่าเริ่มต้น ไม่หายไป
  animation ของปุ่ม / ผลลัพธ์ / popup ยังทำงาน (ต้องการปิดทั้งหมดให้ใช้ "ลดการเคลื่อนไหว" ของเครื่องเหมือนเดิม)
- จำค่าใน localStorage (`cpu-scheduler-motion`) และใส่ `data-motion="off"` ที่ `<html>` ตั้งแต่ใน `<head>` จึงไม่เห็นพื้นหลังขยับแวบหนึ่งตอนเปิดหน้า
  โค้ดอยู่ใน `js/theme.js` (ไฟล์เดียวกับธีม เพราะเป็นค่าหน้าตาที่ต้องใส่ก่อนหน้าเว็บแสดงผลเหมือนกัน)
- สวิตช์ใช้ class ใหม่ `.toggle-switch` (รางคอรัล + ปุ่มกลมขวา = เปิด / รางเรียบ + ปุ่มกลมซ้าย = ปิด)
- ล้างข้อมูล CPU ไม่เปลี่ยนค่านี้ (เหมือนภาษาและธีม)
- วงแหวนในภาพชิปอยู่ใน `<symbol>` + `<use>` (shadow tree) selector ที่อ้างถึง `<html>` เข้าไม่ถึง จึงหยุดด้วยตัวแปร `--ring-animation: none` แทน
  (รอบแรก AI ใช้ selector ธรรมดา วงแหวนยังหมุน ผู้ใช้จับได้ — ดู AI-040)
